# v1.2.0 — The algorithm Ed25519 of the identity token

Base: release 1.1.0. This release changes the signature algorithm that the access of humans accepts (`access.mode = "authzen"`). The open mode does not change.

## Breaking changes

- The header `alg` of the identity token is `Ed25519` or `ES256`. The name `EdDSA` is deprecated by RFC 9864, 4.1.2. ChDash refuses a token with `alg` equal to `EdDSA`, also when the signature is valid. The log line `access.unauthenticated` gives the reason `algorithm`, and the answer is `401`.
- ProcurAuth 9.2 and its decision 36 give the same rule. The portal 5.0.0 and later sign the token with `Ed25519`. An issuer that still signs with `EdDSA` must change its header before it uses this version. An earlier ChDash does not accept the name `Ed25519`: use this version with the portal 5.0.0 and later.

## What does not change

- The keys. The configuration key `identity.public_keys` still holds Ed25519 or P-256 public keys in PEM. The same key signs the token under the new name.
- The checks of `iss`, `aud`, `exp`, the life of the token, `typ`, `crit` and the other members of the header.

## Validation

- `chdash_access_test`: the header of each test token is `Ed25519`, and a new case shows that a token with `EdDSA` is refused with the reason `algorithm`. The native tests of the sanitizer image pass (576 checks, no failure).
- The backend and browser tests use the name `Ed25519` for their tokens. They were not run for this release.
