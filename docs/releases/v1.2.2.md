# v1.2.2 — Only the actions that ChDash serves

Base: release 1.2.1. The document `GET /.well-known/access-actions` lists only the actions that the configuration turns on (ProcurAuth 5.2a). Before, it listed all 12 actions, also the MCP actions when `mcp.enabled` was `false`. A system that shows a form for grants, for example the portal, then offered rights that did nothing.

## What changes

- The document of the actions has the published actions only. The table in `docs/access.md` gives the condition of each action:
  - `explorer.read`: the Explorer is on.
  - `system.read` and `system.kill_query`: `system.enabled` is `true`.
  - `observability.read`: the traces, the logs or the metrics are on for one host at least.
  - `library.read`: one query library is enabled. `library.write`: one enabled library is writable.
  - `mcp.keys.read` and `mcp.usage.read`: `mcp.enabled` is `true`. `mcp.keys.write`: also `mcp.keys.mode` is not `static`.
  - `query.run.read`, `query.run.write` and `query.export`: always.
- The questions to the PDP follow the document. The batch of the navigation and the `actions` of `GET /api/version` have the published actions only. The navigation hides a page whose actions are not published.
- A system that holds grants keeps a grant for an action that is not published. The grant applies again when the action is published again. A change of these settings needs a restart of ChDash.

## Upgrade

- With `mcp.enabled = false` (the default), the three MCP actions leave the document. A grant on one of them stays in the system that holds the grants and does nothing.
- A page of a feature that is off is hidden for every human, also for a human that holds all the actions. This applies to the Traces, Logs and Metrics pages when no signal is on, and to the MCP pages when MCP is off.

## Validation

- `chdash_access_test`: the document and the questions for each feature, on and off. The backend test of the document uses the configuration of the access tests: the Explorer, the System page and MCP are on, and the library and the signals are off.
- The tests of the 1.2.1 release (TLS to ClickHouse) are unchanged.
