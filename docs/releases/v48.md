# v48 — Readable activity and work distribution

Base: the exact `Clickhouse-dash-v47-full.zip` source archive. The v45–v47
summary collection, trace completion and same-parent instance grouping remain
in place. There are no API, database or C++ changes in this release.

## Behavior

Pipeline now separates two questions:

- **When was activity observed?** A compact histogram uses one shared time axis.
  Height and shade encode processor work density within recorded summary
  windows. The summary resolution is always visible. These windows can contain
  unknown gaps and are not exact individual calls or CPU utilization samples.
- **How much work did each stage perform?** A separate work bar shows accumulated
  processor time and its percentage of total recorded work. This includes stages
  whose trace association is unavailable. Wait maxima remain separate numbers.

Full-query, zoom, pan, end-of-query and stage-focus controls make short final
operations inspectable. Time labels gain precision while zooming. Sorting by work
keeps the original pipeline ordinal and does not move activity on the time axis.
Work totals remain for the whole query while zoomed.

Old exports with first/last summaries use dashed, unfilled ranges. They never
become solid activity or contribute to the histogram. New profiling runs are
required to obtain the time-bucketed summaries. Missing stage associations and
partial collection are explicitly described as unavailable or incomplete.

## Calculation and rendering

Summary density is summed active time divided by the observed first-to-last
window duration. Processor count is not simultaneous-lane capacity, so it is
not used as a utilization denominator. Work within each summary window is
uniformly projected into at most 192 display cells. Contributions from overlapping
windows are additive and gaps between windows are retained at display resolution.
This projection is an estimate, never a reconstruction of unknown intra-window
gaps. Eight SVG paths per row bound the number of drawing elements. Very short
events retain a visible marker and the original timestamp.

## Validation

- 415 Python harness checks passed; one existing check skipped.
- 27 deterministic Node model tests passed, including missing/ambiguous timing,
  legacy envelopes, work shares, gap preservation, zoom clipping, overlap,
  zero-duration events and configured processor/summary caps.
- Chromium replay of the supplied `query (6)(1).zip` and `query (7).zip` exports:
  legacy ranges, density differences, final stages, zoom/pan/focus, unchanged
  work totals while zoomed, work sorting and the absence of fabricated timestamps.
- Dark/light rendering at 1440, 1024 and 390 pixels: shared ruler alignment,
  sticky header, contained horizontal scrolling and no browser exceptions.
- Patch applied to a fresh v47 copy, then revalidated against the working source.

No live ClickHouse server was used. Recorded exports were replayed locally;
the server-side collection code is unchanged.

## Apply

From the repository root containing `src/` and `tests/`:

```bash
git apply --check /path/to/Clickhouse-dash-v47-to-v48.patch
git apply /path/to/Clickhouse-dash-v47-to-v48.patch
```

Rebuild/restart the application to refresh the embedded frontend assets. There
is no migration. If your checkout is older than v47, use the full archive or
bring it to v47 before applying this incremental patch.
