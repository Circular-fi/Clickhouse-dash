# v48 — Readable activity and work distribution

Base: the exact `Clickhouse-dash-v47-full.zip` source archive. The v45–v47
summary collection, trace completion and the grouping of same-parent instances
stay in place. This release has no API, database or C++ changes.

## Behavior

The pipeline now separates two questions:

- **When was activity observed?** A compact histogram uses one shared time axis.
  Height and shade encode processor work density within recorded summary
  windows. The summary resolution is always visible. These windows can contain
  unknown gaps and are not exact individual calls or CPU utilization samples.
- **How much work did each stage perform?** A separate work bar shows accumulated
  processor time and its percentage of total recorded work. This includes stages
  whose trace association is unavailable. Wait maxima stay separate numbers.

Full-query, zoom, pan, end-of-query and stage-focus controls let the user inspect
short final operations. Time labels gain precision when the zoom level increases.
The work sort keeps the original pipeline ordinal and does not move activity on
the time axis. Work totals cover the whole query, even when the view is zoomed.

Old exports with first/last summaries use dashed, unfilled ranges. They never
become solid activity or contribute to the histogram. Make new profiling runs to
get the time-bucketed summaries. The view explicitly labels missing stage
associations and partial collection as unavailable or incomplete.

## Calculation and rendering

Summary density is summed active time divided by the observed first-to-last
window duration. Processor count is not simultaneous-lane capacity, so it is
not used as a utilization denominator. Work within each summary window is
uniformly projected into at most 192 display cells. Contributions from overlapping
windows are additive and gaps between windows are retained at display resolution.
This projection is an estimate, never a reconstruction of unknown intra-window
gaps. Eight SVG paths per row limit the number of drawing elements.

Very short events retain a visible marker and the original timestamp.

## Validation

- 415 Python harness checks passed; one existing check skipped.
- 27 deterministic Node model tests passed. The tests cover missing/ambiguous
  timing, legacy envelopes, work shares, gap preservation, zoom clipping, overlap,
  zero-duration events and configured processor/summary caps.
- Chromium replay of the supplied `query (6)(1).zip` and `query (7).zip` exports.
  The replay covers legacy ranges, density differences, final stages, zoom/pan/focus,
  unchanged work totals while zoomed, work sorting and the absence of fabricated timestamps.
- Dark and light rendering at 1440, 1024 and 390 pixels. The check covers shared
  ruler alignment, sticky header, contained horizontal scrolling and no browser exceptions.
- Applied the patch to a fresh v47 copy and revalidated it against the working source.

This validation used no live ClickHouse server. Local replay used the recorded
exports. The server-side collection code did not change.

## Apply

Go to the repository root that contains `src/` and `tests/`:

```bash
git apply --check /path/to/Clickhouse-dash-v47-to-v48.patch
git apply /path/to/Clickhouse-dash-v47-to-v48.patch
```

Rebuild and restart the application to refresh the embedded frontend assets.
There is no migration. If your checkout is older than v47, use the full archive.
You can also bring the checkout to v47 before you apply this incremental patch.
