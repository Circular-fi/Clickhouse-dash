# v49 — Compact processors and bounded Pipeline rendering

Base: the exact `Clickhouse-dash-v48-full.zip` source archive. Processor
collection, activity resolution and Pipeline timing semantics are unchanged.

## Behavior

Processor data now uses the same transport principles as compact spans: one
shared string dictionary, positional rows and relative timestamps. The new
`processors_compact` block retains every processor field, graph identity,
counter and recorded summary window. Unlike the trace display LOD, this
encoding does not merge or discard processor activity windows. UInt64 values
beyond JavaScript's exact integer range are transported as decimal strings.

Normal analysis responses omit the expanded processor arrays. Debug exports
retain them alongside the compact data for diagnosis. The frontend can still
read older object-based exports and reports unsupported or malformed compact
formats explicitly.

The browser iterates summary windows without retaining a second expanded
summary array. Decoded data and the Pipeline model are cached across tab
switches. Above 150 stages, only visible rows plus overscan are mounted and
drawn; all stages remain available through scrolling and sorting. Closing the
dialog releases its data, DOM and observers. Older in-flight responses cannot
replace a newer query or repopulate a closed dialog.

## Measured payload size

The following measurements cover only the processor and processor-summary
blocks, using minified JSON and gzip. They are not whole-response or Debug ZIP
sizes. Compact sizes include the schemas and string dictionary.

| Supplied export | Expanded JSON (bytes) | Compact JSON (bytes) | JSON reduction | Expanded gzip (bytes) | Compact gzip (bytes) |
| --- | ---: | ---: | ---: | ---: | ---: |
| `query (6)(1).zip` | 68,065 | 13,609 | 80.01% | 3,079 | 2,989 |
| `query (7).zip` | 347,623 | 36,890 | 89.39% | 17,294 | 13,613 |

The smaller legacy export already compresses well with gzip. The newer
bucketed export also saves 21.29% after gzip. Debug exports intentionally
include expanded originals, so these reductions describe the normal API's
processor block.

## Validation

- 418 Python harness checks passed; one existing check skipped.
- 27 Pipeline model tests and 8 compact-codec tests passed. The latter used
  the actual C++ encoder, including 10,000 processors and 65,536 windows,
  exact UInt64 values, Unicode/NUL strings, graph scopes and activity gaps.
- Both supplied exports round-trip through the C++ encoder with every
  processor and summary field preserved. Their semantic Pipeline models
  match the expanded-payload models.
- The optional `chdash_processor_codec_test` CMake target configured and
  compiled successfully. The modified API translation unit also passed a
  C++ syntax compilation against the project's pinned dependencies.
- Chromium replay covered compact-only API responses, legacy data,
  zoom/pan/focus/sorting, dark/light themes and 1440/1024/390-pixel viewports.
  A 10,000-stage fixture mounted 26 rows in the tested desktop viewport;
  scrolling to the final stage, sorting and resizing remained functional.
- Dialog checks covered cached tab switching, close/reopen, stale responses
  and malformed compact payloads. No browser exceptions were observed.
- The incremental patch was applied to a fresh v48 snapshot. Its resulting
  source matched the release archive, and the harness was rerun there.

No live ClickHouse server or full application rebuild was used for validation.
Collection SQL is unchanged; the actual C++ serializer and browser integration
were exercised with recorded exports.

## Apply

From the v48 repository root containing `src/` and `tests/`:

```bash
git apply --check /path/to/Clickhouse-dash-v48-to-v49.patch
git apply /path/to/Clickhouse-dash-v48-to-v49.patch
```

Rebuild/restart the application so the backend and embedded frontend update
together. No database migration is required. For a checkout older than v48,
use the full archive or update to v48 before applying this incremental patch.
