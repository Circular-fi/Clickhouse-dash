# v1.5.1 — Small corrections

Base: release 1.5.0. This release has two small changes. It follows the rule of the retry that ProcurAuth made explicit, and it adds one field to the log.

The version of the product comes from the tag. The release workflow reads the tag `v1.5.1` and gives `1.5.1` to the build (`CHDASH_SEMVER_VALUE`). No file of the repository holds the number of the build.

## What changed

- **The log line `access.decision` has the field `permission_only`.** The field is `true` for the question of an other permission (ProcurAuth 5.5a), for example `query.run.read` of `export_query`. It is present only when it is true. A reader of the log can now tell the question of an other permission from the question of the use. The field is in `docs/access.md` ("Logs and traces").
- **The retry after an approval repeats one control argument.** The agent calls the tool again with the same arguments and with exactly one of `approval_ref`, `lease_s` and `until`. Without one of them, the call gets the tool error `invalid_argument`, also when the approval waits. The behaviour did not change. The text did: the description of each tool and the schema of `approval_ref` and `lease_s` in `tools/list` now say it. `docs/mcp.md` and `docs/access.md` say it too.

## Notes

- The tests of conformance use the ProcurAuth commit `1bdfe61`. The cases U34 and U35 have a step for a tool, and they pass for the tool `export_query`. Each variant has 117 cases: 116 passed, 0 failed, 1 skipped (U117).
