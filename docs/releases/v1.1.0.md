# v1.1.0 — The hosts in the access of humans

Base: release 1.0.8. This release changes the resources of the access of humans (`access.mode = "authzen"`). The open mode does not change.

## Breaking changes

- Each question to the PDP names the host. A database question has `properties.ancestors` = `[service, host]`. A host question has `type: "host"`, the name of the `clickhouse.host` block as its id, and the ancestors `[service]`. Only the query library and the MCP keys and usage stay on the service. Refer to [access.md](../access.md#the-resource-of-each-action) for the table of each action.
- `GET /.well-known/access-actions` has a top-level `resource_types` list: `host` (parent `service`) and `database` (parent `host`). Each action lists its valid types. `query.export` lost the type `database`: ChDash never asked it for a database.
- A grant of one level on a database (`service:<id>/database:<name>`) covered that database on every host. It now covers nothing. Give it again on the database of one host: `service:<id>/host:<host>/database:<name>`.
- Update the PDP before ChDash. The PDP must read `properties.ancestors`, the match `"subtree"` of the context and the tree of the list of actions (MCP server contract, section 11).
- In the authzen mode, a `clickhouse.host` name must have 1 to 256 bytes of UTF-8. A longer name stops the start. `access.identity.audience` must be UTF-8.

## Behavior

- `GET /api/hosts`, `GET /api/hosts/stream`, the host picker and the hosts of `GET /api/mcp/meta` show only the hosts on which the human holds one action, on the host or below it. One batch of the PDP with `"context": {"match": "subtree"}` gives these decisions, and the cache keeps them. A grant on one database thus shows its host.
- The match `"subtree"` only shows or hides the navigation. Each operation asks with the match `"node"` on its exact resource. The key of the cache and the log line `access.decision` hold the match.
- A request for a hidden host gets the answer of a host that does not exist: `403` with the action of the route.
- The host picker of each page shows only the hosts on which the human holds one action of that page.
- `GET /api/version` gives `features.access.hosts`, the decisions of each visible host. `features.access.actions` is `true` when the human may use the action on the service, on one host or below one host.
- A page of the navigation needs its action on the service or on one host.
- `readonly = 1` applies to a run without `query.run.write` on its host. For the names of the editor of one database, the rule applies to that database of the host.
- The filter of the databases of 1.0.8 (storage map, graph, names of the editor, card of a table) asks for the host and for each database of the host.
- The key of the cache of the decisions holds the whole path of the resource, so two hosts never share an answer.
- The log line `access.decision` gives the resource as its path, for example `service:db/host:prod/database:analytics`.
- A key of the MCP page asks the PDP for the host of the key and for its databases on that host.

## Validation

- `chdash_access_test`: the resources, the paths, the valid ids, and a PDP of the tests with the prefix rule of the grants. The cases are two hosts, a grant on one host, a grant on one database of one host, a grant on the service and the one-level grant of 1.0.8.
- `test_access.py`: the same cases on a server with two hosts and the fake PDP, which applies the prefix rule and the match `"subtree"`. A grant on one database shows its host, opens that database, and refuses another database and a run on the host.
