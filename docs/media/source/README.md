# Presentation video: sources

`docs/media/chdash-presentation.mp4` (1920x1080, 30 fps, about 75 s) is made of **real screen recordings** of ClickHouse Dash,
filmed by a choreographed Playwright script, and put together with Hyperframes (the `brag` skill, polished tone, `--voice`).
Every page is shown whole (the full 1920x1080 frame of the browser, scaled into the video frame); nothing is cropped or zoomed.
The motion design (title and closing cards, callouts, page switcher, captions, transitions) is drawn around the footage.

```
record/        the choreography: Playwright + Chrome, one script per scene (scenes/*.mjs), the fake cursor, the capture
server/        the configuration of the demo server (one host "prod-eu-1", MCP, a writable query library)
narration/     script.txt (the voice, line by line) and tts.sh (Kokoro voice + Whisper word times)
composition/   the Hyperframes project (index.html is generated by build.mjs; assets are generated or copied, not committed)
build.mjs      places callouts, voice, sound effects and cuts on the clock of the clips, of the words and of the music beats
composition.css, sfxbed.py   the style of the composition and the mixer of the sound effects
MUSIC-LICENSE.md  what is known about the music, and what is not
```

## How the footage is made

* **Capture.** Chrome (headless) loads the page at 1600x900 CSS pixels with a device scale of 1.2, so the browser frame is
  exactly 1920x1080 pixels and the text is as large in the video as on a 1080p screen. `Page.startScreencast` (JPEG, quality 96)
  delivers every frame that Chrome paints (35 to 55 per second); `record/lib.mjs` writes them with their timestamps and
  `ffmpeg` turns them into a constant 60 fps clip. Playwright's own `recordVideo` was not used: it is a low-bitrate VP8 stream.
* **Cursor.** Playwright never draws the mouse. An init script puts a cursor and click ripples in the page itself, so they are in
  the footage. The mouse moves along eased curves (`glide`), the typing has a human rhythm (`humanType`), and every wait is
  marked (`wait`) so that `prep.mjs` can play waits and typing faster, and keep the moments that matter (a query running) real.
* **Marks.** The choreography names the moments of a scene (`rec.mark("run")`), the clicks, the typing and the boxes of the real
  elements (`rec.rect`). `prep.mjs` writes them, on the clock of the cut clip, to `<scene>.cut.json`; `build.mjs` places the
  callouts and the voice on them.
* **The host.** The page is reached as `dash.example.com` (Chrome `--host-resolver-rules`) so that the MCP page shows a neutral
  endpoint. The server has one host named `prod-eu-1` ("Production EU").

## Re-record and re-render

Needs: the test ClickHouse stack of `tests/` (compose, running), Docker, Node 22, Chrome, ffmpeg, Python 3 with numpy, and the
Hyperframes CLI (`npx hyperframes`, 0.8.x). The music file comes from the `brag` skill (see `MUSIC-LICENSE.md`).

```bash
# 1. the server of the demo (image of this worktree, version 1.0.0) and its ClickHouse users (scratch users of the test stack)
docker build -f tests/Dockerfile.source -t chdash-video:local \
  --build-arg CHDASH_SEMVER=1.0.0 --build-arg CHDASH_GIT_SHA=3f9a1c7e5b2d84a6c0e9f17b3d52a8c4e6f09b1d .
record/setup-clickhouse.sh up        # creates dash_runner / dash_system / dash_mcp on the test ClickHouse
docker run -d --name chdash-video-server --network chdash-tests_default -p 127.0.0.1:18290:8080 \
  -e CHDASH_CONFIG_FILE=/config/chdash.hcl -v "$PWD/docs/media/source/server/chdash.hcl:/config/chdash.hcl:ro" \
  -v chdash-video-data:/data chdash-video:local
record/seed-server.sh                # the library folders and queries, the three MCP keys

# 2. film (each scene is one continuous recording; about 20 s each)
cd docs/media/source/record && npm i
./workload.sh                        # a few query shapes in the last hour, for the System scene
CLIP_DIR=$PWD/clips node run.mjs query_a query_b save explorer traces logs_metrics system mcp
CLIP_DIR=$PWD/clips node run.mjs --prep-only save     # re-cut only (speeds are in each scene's `cut`)

# 3. voice and music
cd .. && ./narration/tts.sh          # the lines without a wav (Kokoro, voice af_heart) and their word times (Whisper)
cp ~/.claude/skills/brag/assets/music/happy-beats-business-moves-vol-12-by-ende-dot-app.mp3 composition/assets/music/bed-src.mp3

# 4. build, mix, check, render
CLIP_DIR=$PWD/record/clips node build.mjs            # writes composition/index.html and the sound effects bed
./finish.sh                                          # carve the music under the voice, check, render both variants, encode
```

Clean up afterwards: `record/setup-clickhouse.sh down`, `docker rm -f chdash-video-server`, `docker volume rm chdash-video-data`,
`docker rmi chdash-video:local`.

A full re-record takes about 10 minutes (a scene is filmed in 15 to 25 s, plus the 60 fps encode), the render about 5 minutes.
