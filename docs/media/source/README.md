# Presentation video: sources

`docs/media/chdash-presentation.mp4` (1920x1080, 30 fps, about 75 s) consists of **real screen recordings** of ClickHouse Dash.
A choreographed Playwright script films the recordings. Hyperframes assembles the video with the `brag` skill, a polished tone and `--voice`.
The video shows each page whole. It scales the full 1920x1080 browser frame into the video frame, and it does not crop or zoom.
A motion design draws the title and closing cards, callouts, page switcher, captions and transitions around the footage.

```
record/        the choreography: Playwright and Chrome, one script for each scene (scenes/*.mjs), the fake cursor and the capture
server/        the configuration of the demo server (one host "prod-eu-1", MCP, a writable query library)
narration/     script.txt (the voice, line by line) and tts.sh (Kokoro voice and Whisper word times)
composition/   the Hyperframes project (index.html is generated by build.mjs; the assets are generated or copied, not committed)
build.mjs      places the callouts, the voice, the sound effects and the cuts on the clock of the clips, of the words and of the music beats
composition.css, sfxbed.py   the style of the composition and the mixer of the sound effects
MUSIC-LICENSE.md  what is known about the music, and what is not
```

## How the footage is made

* **Capture.** Chrome (headless) loads the page at 1600x900 CSS pixels with a device scale of 1.2. The browser frame is exactly 1920x1080 pixels, and the text is as large in the video as on a 1080p screen. `Page.startScreencast` (JPEG, quality 96) delivers every frame that Chrome paints (35 to 55 per second). `record/lib.mjs` writes the frames with their timestamps, and `ffmpeg` makes a constant 60 fps clip from them. This method does not use Playwright's own `recordVideo`, because that makes a low-bitrate VP8 stream.
* **Cursor.** Playwright never draws the mouse, so an init script puts a cursor and click ripples in the page itself, and they appear in the footage. The mouse moves along eased curves (`glide`). The keystrokes follow a human rhythm (`humanType`). The choreography marks every wait (`wait`), so that `prep.mjs` can play waits and keystrokes faster. The marks also keep the moments that matter, for example a query that runs, at real speed.
* **Marks.** The choreography names the moments of a scene (`rec.mark("run")`). It also names the clicks, the keystrokes and the boxes of the real elements (`rec.rect`). `prep.mjs` writes the marks to `<scene>.cut.json`, on the clock of the cut clip. `build.mjs` places the callouts and the voice on those marks.
* **The host.** Chrome reaches the page as `dash.example.com` through `--host-resolver-rules`. This gives the MCP page a neutral endpoint. The server has one host. Its name is `prod-eu-1` ("Production EU").

## Re-record and re-render

Requirements:

* the test ClickHouse stack of `tests/` (compose, started)
* Docker
* Node 22
* Chrome
* ffmpeg
* Python 3 with numpy
* the Hyperframes CLI (`npx hyperframes`, 0.8.x)

The `brag` skill gives the music file. See `MUSIC-LICENSE.md`.

```bash
# 1. Build the demo server image of this worktree, with the version and SHA that the header shows.
docker build -f tests/Dockerfile.source -t chdash-video:local \
  --build-arg CHDASH_SEMVER=1.0.0 --build-arg CHDASH_GIT_SHA=3f9a1c7e5b2d84a6c0e9f17b3d52a8c4e6f09b1d .
record/setup-clickhouse.sh up        # create the scratch users dash_runner, dash_system and dash_mcp on the test ClickHouse
docker run -d --name chdash-video-server --network chdash-tests_default -p 127.0.0.1:18290:8080 \
  -e CHDASH_CONFIG_FILE=/config/chdash.hcl -v "$PWD/docs/media/source/server/chdash.hcl:/config/chdash.hcl:ro" \
  -e CHDASH_VIDEO_RUNNER_PASSWORD=video_runner_pw -e CHDASH_VIDEO_SYSTEM_PASSWORD=video_system_pw -e CHDASH_VIDEO_MCP_PASSWORD=video_mcp_pw \
  -v chdash-video-data:/data chdash-video:local
record/seed-server.sh                # seed the library folders, the queries and the three MCP keys

# 2. Film. Each scene is one continuous recording of about 20 s.
cd docs/media/source/record && npm i
./workload.sh                        # run a few query shapes in the last hour, for the System scene
CLIP_DIR=$PWD/clips node run.mjs query_a query_b save explorer traces logs_metrics system mcp
CLIP_DIR=$PWD/clips node run.mjs --prep-only save     # cut again only (speeds are in each scene's `cut`)

# 3. voice and music
cd .. && ./narration/tts.sh          # make the lines that have no wav, with Kokoro voice af_heart and Whisper word times
cp ~/.claude/skills/brag/assets/music/happy-beats-business-moves-vol-12-by-ende-dot-app.mp3 composition/assets/music/bed-src.mp3

# 4. build, mix, check, render
CLIP_DIR=$PWD/record/clips node build.mjs            # write composition/index.html and the sound effects bed
./finish.sh                                          # carve the music under the voice, check, render both variants and encode
```

Remove the demo resources afterwards. Run these commands:

* `record/setup-clickhouse.sh down`
* `docker rm -f chdash-video-server`
* `docker volume rm chdash-video-data`
* `docker rmi chdash-video:local`

A full re-record takes about 10 minutes. One scene takes 15 to 25 s to film, plus the 60 fps encode. The render takes about 5 minutes.
